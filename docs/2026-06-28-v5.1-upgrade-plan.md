# V5.1 升级方案 — 多因子框架增强 + 数据补全

> **创建日期：2026-06-28　|　最后更新：2026-06-28**
> 分支：`codex/strategy-v5.1-iteration`　|　基线数据：`quant.duckdb:market_daily`（AkShare qfq，5.56M 行，5368 股，2022-01-04~2026-06-26）

## 0. 背景与目标

V5 已重建出干净的全市场复权行情。本次（V5.1）做两件事：

1. **框架代码升级**：把从「成功案例」（同事的多因子策略 + NSGA-II HPO 实验，见 `Desktop/data/_paper`、`_alpha_decay`、66 个 Optuna `.db`）学到的方法，落进我们现有框架。
2. **数据补全**：补齐基本面（PE/PB/ROE，给 value/quality 因子）、可交易性（ST/停牌/行业）、退市股（消除幸存者偏差）。

### 指导原则（不可违背）

- **他们的信号广度 ⊕ 我们的验证纪律。** 他们信号丰富但缺防过拟合门禁；我们有 `null_test`/`deflated_return`/`holdout`/`overfitting_score` 但信号太薄。两者结合。
- **追求「恰当的复杂度 + 验证过真有效」,不是「看起来高级」。** 铁证：他们最精密的 NSGA-II 优化版（3fopt）实盘输给等权（3f_eq）。复杂度必须被验证门禁拦一道。
- **绝不用未来数据**：所有因子/IC/权重只能用截至当日的历史。

### 关键架构决策（2026-06-28 与用户确认,不可擅改）

1. **LLM 退出紧循环,只做离线因子发现（学成功案例）。** AI（Claude）用来**离线提新因子点子 → 人审 → 进因子库**,以及**解读归因**。量化循环本身**纯算法**（IC自适应 + 多目标HPO + 风控 + 验证）,循环内**不调 LLM**。这避免「LLM 每轮提假设」带来的多重检验/过拟合风险,也不烧 token。对应改动：现有 `claude_proposer` 从「循环内逐轮提假设」改为「**离线因子建议器**」,产出落到一个**人审过的因子库**,量化循环只从因子库取用。
2. **因子权重由 IC 自适应决定,HPO 只调结构参数**（top_n/换仓/IC lookback/floor/止损/仓位档）。不让 HPO 直接搜因子权重——那正是他们 3fopt 过拟合的根源。
3. **验收以指数相对为主**：α/IR 达标才算赢,绝对收益做参考（防牛市靠 β 自欺）。

## 1. 工作流 A：框架代码升级

**新架构链路（紧循环纯算法,LLM 在循环外）**：
```
[循环外·离线] AI 因子建议器(claude_proposer 改造) → 人审 → 因子库
                                                      │
[紧循环·纯算法] 因子库 → factor_panel(A1) → IC自适应权重(A2)
                → 多目标HPO 调结构参数(A3) → 风控叠加(A5)
                → factor_backtest → 指数相对评估(A4) → 验证门禁(null/holdout/deflated)
                → A6 每月滚动重优化 → A7 分指数池
```
现有 `orchestrator.run_pipeline`/`refinement.run_refinement` 保留为编排骨架,但**因子来源从「每轮 LLM 提案」改为「从人审因子库取用」**;`hpo` 升级见 A3。

### A1. 多因子面板 `factor_panel`（新增 `factor_panel.py` + 表）

**做什么**：从 `market_daily`（+ 后续基本面表）算出截面因子,落到 duckdb 表 `factor_panel(stock_code, trade_date, <因子列...>)`,作为回测/打分的统一输入 `frame`。

**因子清单**（对齐他们的 value/momentum/quality/technical + 我们能全市场算的）：

| 类别 | 因子 | 来源 | 本期可算? |
|---|---|---|---|
| momentum | ret_20d, ret_60d, mom_120_20（12-1 动量,跳过近月） | price | ✅ |
| reversal | ret_5d（短期反转,反向） | price | ✅ |
| volatility | vol_20d, vol_60d（低波动,反向） | price | ✅ |
| liquidity | turnover_rate, amount_20d（反向,低流动性溢价） | market_daily | ✅ |
| technical | px_to_ma20, px_to_ma60（均线乖离） | price | ✅ |
| value | ep=1/pe, bp=1/pb | 基本面表 | ⏳ 待 A 组数据 |
| quality | roe, netprofit_yoy | 基本面表 | ⏳ 待 A 组数据 |

**验收**：`factor_panel` 覆盖全市场每年；各因子空值率 < 5%（除停牌）；无未来函数（用 `lag` 确保 t 日因子只用 ≤t 数据）。

### A2. IC 自适应加权模块（新增 `ic_weighting.py`）

**做什么**：对每个因子,滚动算 IC = 截面上「因子 z-score」与「未来 N 日收益」的秩相关（Spearman）；对 IC 做 EMA 平滑 + 地板,产出**逐期动态权重**。

**接口**（与现有 `FactorConfig.weights` 兼容,可作为权重来源的一种）：
```
compute_ic_series(panel, factor, forward_days=20, lookback=60) -> Series[date->IC]
ic_adaptive_weights(panel, factors, lookback=60, smooth_alpha=0.3, floor=0.01) -> DataFrame[date x factor]
```
参数对齐他们：`ic_lookback=60, ic_smooth_alpha=0.3, ic_floor=0.01`。

**验收**：单测——构造一个「已知有效因子 + 一个纯噪声因子」,有效因子权重显著高于噪声；权重在 t 日只用 < t 的 IC（无未来函数）。

### A3. HPO 升级多目标 NSGA-II + 强制接验证门禁（改 `hpo.py`、`orchestrator.py`）

**做什么**：
- `optimize()` 增加 `multi_objective=True` 路径：用 `optuna.samplers.NSGAIISampler`,**双目标 = (MAXIMIZE 走查OOS收益, MINIMIZE 走查最大回撤)**,返回**帕累托前沿**,而非单点。
- 从前沿按规则选点（默认「在满足回撤约束下收益最高」的膝点）。
- **门禁强制化**：`orchestrator` 里,被选中的配置必须依次过 `null_test`（随机数据通过率低）、`holdout`（留出期不崩）、`deflated_return`、`overfitting_score`,任一不过则标记「不可信」,不进可部署集。

**向后兼容**：保留原 TPE 单目标路径（默认 `multi_objective=False`),不破坏现有调用。

**验收**：多目标返回 ≥1 个帕累托解；在合成数据上,纯噪声因子组合被 `null_test` 拦下（通过率 > 阈值 → 判不可信）。

### A4. 指数相对评估（改 `evaluation.py` + 新增基准拉取）

**做什么**：
- 新增 `benchmark.py`：用 akshare `index_zh_a_hist` 拉指数日线（沪深300=000300/中证500=000905/中证1000=000852 等）,缓存到 duckdb 表 `index_daily`。
- `evaluation` 增加相对指标：超额收益 α = 策略 − 基准、跟踪误差 TE、**信息比率 IR = α/TE**、超额最大回撤、对基准胜率。
- `AcceptanceCriteria` 增加可选门槛：`min_information_ratio`、`min_excess_return`,与绝对收益门槛并存（可配置以哪个为主）。

**验收**：对一条已知 equity 曲线 + 已知指数,α/IR/TE 计算与手算一致；用今天验证过的数字回归测试（csi1000_3f_eq +175.8% vs 中证1000 +14.1% → α≈+161.7pp）。

### A5. 风控叠加（改 `factor_backtest.py`）

**做什么**：在 `run_factor_backtest` 持仓与换仓逻辑里,加两个可选叠加（默认关,可配置）：
- **两段式移动止损**：`tier1_trigger=0.15/tier1_floor=0.05`、`tier2_trigger=0.30/tier2_pullback=0.10`（对齐他们 state.json）。
- **波动率仓位调节**：按个股近 20 日波动相对历史分位,分档缩放仓位(`vol_tier1_pct=50→scale0.7`,`vol_tier2_pct=80→scale0.5`)。

**验收**：开启止损后,在一段已知大回撤行情上,最大回撤显著下降且不引入未来函数（止损判定只用 ≤t 价格）。

### A6. 每月滚动重优化（新增 `rolling_reopt.py` + 改 `orchestrator.py`）

**做什么**：对齐他们的 `reopt_*_<月份>` 做法——不是一次性优化好就锁死参数,而是**按月滚动重跑 HPO**：每个月初,用「截至该月的历史」重新优化参数,部署到下个月,再到下月初用新数据重优化。这才是真正可部署的走查（walk-forward deployment),也能让 IC 自适应权重 + HPO 参数随市场风格更新。

**接口**：
```
rolling_reoptimize(panel, proposer, space, criteria, start, end, step="MS",
                   lookback_months=24) -> List[ReoptSnapshot]
# 每个 snapshot: as_of 月、用截至 as_of 的数据优化出的 config、下月实际表现
```
**关键纪律**：每次重优化只用 `as_of` 之前的数据;下月表现是纯样本外。把这些「逐月样本外」拼成一条**真·样本外净值曲线**,这是最诚实的业绩证据（比单段 holdout 更强）。

**验收**：产出逐月样本外净值;对比「一次性优化锁死」vs「滚动重优化」两条曲线;无未来函数（重优化窗口严格 ≤ as_of）。

### A7. 分指数池优化（改 `orchestrator.py` + universe 配置）

**做什么**：对齐他们 `factor_wf_v1_<universe>_*`——**每个指数池单独跑整条流水线并单独调参**,而非全市场一锅烩。池来自 B2/B3 的成分（沪深300/中证500/中证1000/科创100/北证50…）。不同池的最优因子权重/参数本就不同（他们数据印证：value 在中证1000 强、动量在别处强）。

**接口**：
```
run_per_universe(universes: list[str], ...) -> dict[universe -> OrchestratorReport]
# 每个池：独立 factor_panel 子集 → 独立 HPO/IC权重 → 独立指数相对评估(对自己的基准)
```
**与 A4 联动**：每个池对**自己的基准**算 α/IR（中证1000 池就对中证1000),不混基准。

**验收**：能对至少 2 个池分别产出独立报告与各自最优参数;参数确实因池而异（验证「分池」的必要性）。

## 2. 工作流 B：数据补全（含第三块「基本面」）

可与工作流 A 并行（A 的代码用价量因子先跑通,value/quality 待 B1 落地后接入）。

### B1. 基本面（PE/PB/ROE）→ 表 `valuation_daily`、`financials`

**做什么**：用 akshare 拉全市场估值与财务（Desktop `_basic/_fina` 太稀疏,只几百只,弃用）。
- 估值：`stock_zh_valuation_baidu`（PE/PB/PS）或等价接口,逐股票拉历史。
- 财务：`stock_financial_analysis_indicator`（ROE、净利同比）逐股票季度。
- 断点续传 + 限速 + 失败清单（复用 `fetch_akshare_history.py` 模式）。

**验收**：全市场覆盖（缺失股列入失败清单）；ROE 对齐季度公告日,回测用时做 point-in-time（只用已公告数据,防前视）。

### B2. ST/停牌/行业 → 补 `normalized` 可交易性字段

**做什么**：
- **停牌** `is_suspended`：由交易日历缺口推导（某股在全市场交易日却无该日数据 = 停牌）。
- **行业** `industry`：akshare 行业成分/个股行业接口。
- **ST** `is_st`：akshare 现状 ST 名单 + 尽力历史（历史 ST 较难,先标注覆盖范围,无法全history则注明）。

**验收**：停牌推导与已知停牌样本核对；行业覆盖率 > 95%;ST 字段注明历史覆盖边界（诚实标注限制）。

### B3. 退市股（幸存者偏差）→ 扩 universe

**做什么**：akshare 沪/深退市名单,拉退市股代码及其在 2022-2026 的历史,纳入 `market_daily` 与 universe。

**验收**：universe 含退市股；回测在含退市股的池上跑,对比纯现存池,量化幸存者偏差幅度。

## 3. 依赖与排期

```
B1 基本面 ─┐
           ├─→ A1 因子面板(全因子) ─→ A2 IC加权 ─→ A3 多目标HPO+门禁 ─┐
价量因子 ──┘                                            ↑              ├─→ A6 每月滚动重优化 ─→ 真·样本外净值
A4 指数相对评估(需 benchmark 拉取) ───────────────────────┘              │
A5 风控叠加（独立,可随时并入 factor_backtest）─────────────────────────┘
A7 分指数池优化（外层包住 A1-A6,每池独立跑一遍）—— 需 B2/B3 的成分股池
B2 ST/停牌/行业、B3 退市股（独立,可并行,提供池成分 + 风控筛选）
```

**落地顺序建议**：
1. 先做 A1（价量因子）+ A2 + A4 + A5 —— 不依赖网络,立刻可跑可测。
2. 同时后台跑 B1/B2/B3 数据拉取。
3. 数据到位后,A1 接入 value/quality,A3 多目标 HPO 全量跑。
4. A6 每月滚动重优化 包在 A3 外层,产出逐月样本外净值（最强业绩证据）。
5. A7 分指数池 包在最外层:对 B2/B3 给出的每个池,独立跑 A1–A6 一整套。

## 4. 总验收（V5.1 完成定义）

- [ ] 框架能在真实 `market_daily` 上跑通：AI 提假设 → IC自适应/多目标HPO → 指数相对评估 → 验证门禁 → 输出「可信/不可信」标签。
- [ ] **A6 滚动重优化**产出逐月**真·样本外净值**曲线（最强业绩证据,胜过单段 holdout）。
- [ ] **A7 分指数池**:至少 2 个池各自独立产出报告与最优参数,且参数因池而异。
- [ ] 复现「等权 vs 优化」对照实验,确认我们的门禁能识别过拟合。
- [ ] 数据：基本面 + 可交易性 + 退市股入库,各自标注覆盖边界。
- [ ] 全程无未来函数（point-in-time）。
- [ ] 新增模块有单测;关键数字有回归测试。
