# 初版架构说明

## 目标

构建一个研究驱动的量化策略生产闭环：

1. 用户输入 KPI 与约束
2. `manager-orchestrator` 生成任务版本
3. `quant-researcher` 输出策略说明
4. `quant-researcher` 与 `strategy-engineer` 联合定义所需数据
5. `data-engineer` 收集并确认数据口径
6. 后续才进入公式化、代码化、回测与审核
7. 审核通过后进入手动监控

## 初版原则

- 先固化流程，不固化量化代码实现细节
- 先定义接口和文档，再决定引擎
- 策略说明优先于模板策略
- 数据就绪优先于代码实现
- 长期记忆是核心基础设施，不是附属功能

## 模块边界

- `workflow`
  - 管理阶段流转与输出目录
- `strategy_brief`
  - 管理研究输出的结构化描述
- `data_spec`
  - 管理数据需求和数据口径决策
- `memory_policy`
  - 管理记忆标签和记忆时机
- `review_packet`
  - 管理审核所需材料
- `signal_monitor`
  - 管理手动触发的监控输出
