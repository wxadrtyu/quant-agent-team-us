01 · 项目定位与现状

这个仓库起源于 A 股日频策略工厂，现包含较多美股研究、验证、观察与报表脚本。两个方向共处一个仓库，但不是同一套可直接替换的数据契约或生产入口。

A 股日频主流程

cli.py 暴露命令；ProjectWorkflow 编排 KPI、策略规格、数据同步、摄取、特征、回测和评估。默认配置见 configs/defaults.yaml。

美股研究扩展

scripts/us_*.py 覆盖数据快照、股票池、策略探索、滚动与随机检验、报告等环节。部分脚本会写 DuckDB 或报告，不能视为无副作用的“查看”命令。

先看代码，再看旧文档。 README.md 与 docs/current-architecture-draft.md 含早期范围和机器路径。它们有历史价值，但不能单独证明当前实现、可运行性或授权状态。例如“生成评审占位文件”不等于通过人工审核。

本说明书描述“在哪里改、如何验证、哪些地方不能越界”。它不替代策略评审记录，也不承诺某个样本、数据源或回测结果具备全市场代表性。

03 · 环境、配置与最小验证

pyproject.toml 声明基础依赖 pandas、numpy、pycryptodome、optuna，可选项包含 pytest、anthropic、yfinance。本次使用 Python 3.12.10 收集测试；虽然声明最低版本为 3.9，部分脚本使用较新的类型语法，移植到 3.9 前应逐文件验证。

新环境先安装项目与测试依赖（安装可能访问包仓库），之后可做不连业务数据源、不运行策略的检查：

python --version
python -m pip install -e ".[test]"
python -m quant_agent_team.cli --help
python -m pytest --collect-only -q
python -m pytest tests/test_db_config.py tests/test_point_in_time.py -q

本次核查：测试收集 226 项；全量测试为 217 通过、9 跳过、6 条 pandas FutureWarning；上述两个定向测试文件共 6 项通过。安装命令是给新环境的操作指引，本次未执行。若不安装而直接从源码运行 CLI，须先将 src 加到 PYTHONPATH；本次在 PowerShell 中用 $env:PYTHONPATH='src' 验证了 --help。测试结果仅适用于本次检出的代码与环境，不代表真实数据链路或策略已获批准。

数据库分层。 A 股摄取/特征路径使用 PostgresCli。其配置读取 QUANT_DB_URL、QUANT_DB_ADMIN_URL、QUANT_PSQL_BIN、QUANT_CREATEDB_BIN；默认值偏向 macOS 本机 PostgreSQL socket。Windows 上应显式配置可用连接和命令路径，不要照抄默认路径。部分因子和美股研究脚本另外使用 DuckDB；它不等于 A 股 PostgreSQL 主库。

美股脚本可能直接导入 duckdb 等库，而这些库并未全部列在 pyproject.toml 的依赖中。运行某个脚本前，先检查其 import、输入文件和写入目标，补齐环境后再做隔离验证；不要把一次本地成功当作可复现安装证明。

run_daily_job.sh 和 install_launchd_daily_job.sh 面向类 Unix / macOS；配置里的 15:30 是预留时点，不代表自动调度已获批准。

04 · A 股日频主链路

  1. 输入与规格： models.py 定义 KPI、策略说明、StrategySpec、规则和审核对象。CLI 的 new-kpi、new-brief、new-spec 生成初始产物；new-spec 生成的是 status=draft 的实现占位，需补全字段和审核。
  2. 依赖规划： dependency_registry.py 与 strategy_data_sync.py 根据规格和数据清单形成同步计划；sync-data 不等于依赖已采集完整。
  3. 数据进入： ingestion.py 处理股票文件增量、原始与标准化行情和冲突记录；base-incremental-ingest、daily-update 会写库和报告。数据源样例与交易约束格式见 inputs/trading_constraints/README.md。
  4. 特征与质量： feature_refresh.py 更新研究特征；data_quality.py 构建质量摘要。缺口、冲突、陈旧数据应保留并分类，不要以填零或静默剔除伪装完整。
  5. 回测与判定： backtest_runner.py 加载行情并模拟策略，evaluation.py 按显式阈值评估。pipeline_v51.py 还提供因子、优化、留出与空值检验的另一条研究路径；不能把这些不同流程的指标混为同一证明链。
  6. 人工审核后才进入监控： new-review 仅创建待审核 Markdown 占位；AGENTS.md 明确未经人工审核不得进入监控池。允许零信号日，应给出原因，不得强行推荐。

有副作用的命令不要当作环境自检。 daily-update、run-backtest、evaluate-backtest、repair-normalized-sync 都会产生产物或修改数据状态；在真实数据上运行前先确定数据库、数据快照、版本和审批范围。

05 · 美股研究与报告扩展

美股路径以脚本和研究产物为主，不应直接套用 A 股日频 CLI 的 PostgreSQL 契约。下面按“职责”导航，不暗示任何脚本已获生产批准。

阶段主要代码二开关注点
数据快照与股票池fetch_us_large_mid_data.py、us_universe.py、us_survivorship_audit.py来源、截面时间、退市证券、动态成员和覆盖率；大中盘/ETF 样本不等于全市场。
候选与验证us_strategy_factory_loop.py、us_rolling_validation.py、us_null_overfit_check.py固定候选定义、成本、折叠、复用样本、重采样和多重比较证据。
研究库与报告us_research_db_ingest.py、us_generate_live_html_report.py前者会写 DuckDB，且表结构不同时有替换逻辑；后者会生成报告。先核查输入、快照和输出路径。
观察/池相关us_live_pool.py、us_build_current_model_portfolio.py存在写入与状态变化风险；仅用于理解代码边界，不能从文件名推断当前可激活状态。

机器绑定与数据权限。 若干美股脚本的参数默认值包含历史开发机的 E:\/G:\ 路径，例如报告脚本的 --db 与 --out-dir。移植时必须显式指定受控路径、检查数据许可证及缺失范围；不要通过拼接另一供应商、填补空 bar 或幸存者筛选来“修复”覆盖率。

研究结果、Paper 观察、真实订单是不同权限层。即使候选通过历史门槛，也仍需独立前瞻影子验证和人工授权；本手册不提供 broker、提交/撤单或池激活的操作配方。

06 · 二次开发配方

增加一个数据源或字段

  1. 先定义来源、授权、交易日/时区、点时可用性、证券身份、单位、修订与缺失语义；不要先写抓取循环。
  2. 在 ingestion.py 或对应的独立美股入口加解析与校验，保持原始证据和冲突处理；不要覆盖异值记录。
  3. 如影响数据依赖和特征，更新 dependency_registry.py、feature_refresh.py 及数据质量规则，并增加空值、重复、时区和未来泄漏测试。

增加一个因子或策略规则

  1. 研究假设先入规格，确认输入字段已存在且交易时可得。A 股因子相关入口包括 factor_library.py、factor_panel.py、factor_scoring.py。
  2. 将执行时点、持有期、成交限制和成本写成可测规则；参考 test_factor_panel.py、test_backtest_costs.py 和 test_point_in_time.py。
  3. 若是美股研究新族，单独登记实验范围与版本，不从已看过的时期重新命名“独立 OOS”；不能为过门槛事后改变分母、价格路径或检验族。

增加评估、审核或报表字段

  1. 先在 evaluation.py 或相应美股验证脚本定义来源和失败含义，避免“缺数据视作通过”。
  2. 保持结构化产物与展示一致；美股 HTML 报告的载荷完整性检查在 validate_payload_integrity()，对应测试见 test_us_live_report_integrity.py。
  3. 若影响监控资格，提交审核证据并等待人工决定；不要让报表外观或分数自动改变池状态。

07 · 质量门槛与权限边界

数据真实性

点时成分、退市、复权、停牌、无成交、缺失时钟须可追踪。无成交的空 bar、拍卖指示价或跨源补洞不是当然可执行价格。

研究诚实性

开发、留出、已看过的历史与真正前瞻期分开；完整记录成本、延迟、容量、回撤、邻域、全局证据与多重比较。失败实验也要留证据。

审批隔离

策略建议、回测通过、观察、Paper/实盘是不同阶段。未获人工审核，不进入监控池；新增第三方 agent/skill 先走 Phase 0 评审。

资产与凭证

数据库、原始数据、压缩包、密钥和日志不纳入代码提交。先核对写入目标，避免研究脚本覆盖用户数据；本手册不保存任何凭证。

项目治理基线见 AGENTS.md；历史原则见 docs/memory_policy.md。新任务先检索长期记忆，阶段结束写入结构化结论；MCP 不可用时本地保底并在恢复后补写。一次文档改动本身不触发策略自动轮训。

08 · 排查与维护清单

现象先核查不要直接做
CLI 子命令与文档不符build_parser()、python -m quant_agent_team.cli --help照抄旧 README 的绝对路径。
数据库连接失败DatabaseConfig.from_env() 和 PostgreSQL 命令可用性在未知连接上执行 ensure_database() 或修复命令。
数据行数或字段异常增量摘要、冲突与质量报表；字段单位和源文件哈希删缺失、填零或静默覆盖冲突。
美股研究/报告不可复现脚本输入参数、硬编码默认路径、数据快照、第三方包和版本把旧输出移植为新环境的合格结论。
候选“通过”但证据不足原始分母、时钟联合覆盖、成本、完整路径及独立前瞻证据自动加入观察/交易池或降低门槛。

提交前最低检查

  • 确认 git status 仅含本次目标文件，没有数据库、密钥、原始包或用户未跟踪文件。
  • 文档中每个路径可在当前仓库找到；所有可执行命令都区分“只读检查”与“会写状态”。
  • 新增行为有测试、反例与来源说明；修改数据契约时同步策略规格、质量规则和报表。
  • 审核状态、记忆记录和前瞻验证计划各自独立，不以单份报告替代。

推荐阅读顺序： 治理规则 → CLI → 工作流 → 目标模块及其 测试 → 本次改动的输入/输出证据。遇到旧文档与当前实现冲突，先核代码和对应测试，再更新说明。
