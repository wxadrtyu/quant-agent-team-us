# 2026-03-30 Event Strategy Options

## Summary

围绕“硬信息事件驱动”形成两条明确方案，并决定先执行第二种低成本验证方案。

## Option 1

`业绩化增强版`

- 目标：把公告事件升级为“业绩预告/快报/超预期强度”研究线
- 核心新增字段：
  - `earnings_event_tag`
  - `earnings_event_direction`
  - `profit_change_lower`
  - `profit_change_upper`
  - `profit_change_mid`
  - 可选进一步扩展到 `surprise_pct / analyst_revision`
- 优点：
  - 更接近真正要验证的“业绩后漂移”机制
  - 可解释性更强
  - 如果有效，更值得长期投入
- 缺点：
  - 需要额外的数据清洗与文本抽取
  - 当前项目还没有现成的业绩强度字段
  - 会先增加数据工程成本，再知道方向是否有边

## Option 2

`现有公告标签快速验证版`

- 目标：先用现有 `announcement_event_tag / policy_event_tag / announcement_count_1d` 验证“正向公告事件延续”是否存在轮廓
- 先做的正向子集：
  - `重大事项::重大合同`
  - `重大事项::签订协议`
  - `重大事项::股权激励进展公告`
  - `重大事项::获得认证`
  - `重大事项::投资设立公司`
  - `policy_event_tag = capital_support`
- 明确排除的负向/噪声子集：
  - `持股变动::股东/实际控制人股份减持`
  - `重大事项::股份质押、冻结`
  - `风险提示::股票交易异常波动`
  - `重大事项::诉讼仲裁`
- 优点：
  - 成本低
  - 能快速判断事件驱动母方向值不值得继续
  - 失败时损失小
- 缺点：
  - 不是业绩策略本身
  - 噪声更大
  - 如果结果差，不能直接推翻“业绩超预期”方向，只能说明当前粗事件代理不够好

## Decision

先执行 `Option 2`。

原因：

- 用户希望避免先投入大量数据工程，再发现方向本身无效
- 当前项目的事件数据已经足够支撑“正向公告事件延续”的第一版快筛
- 若 `Option 2` 完全无轮廓，再决定是否停止该母方向；若已有轮廓，再考虑升级到 `Option 1`

## Next Step

- 将 `Option 2` 落成正式 research brief
- 基于现有事件标签构建第一版策略 spec，并做短窗快筛
